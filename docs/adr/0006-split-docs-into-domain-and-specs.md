# ADR-0006 ドキュメントを業務知識とシステム仕様に分けて構成する

## ステータス

承認済み (2026-08-17)

## 背景

`docs/` には概要・用語集・ビジネスロジック仕様・受講期限の扱いを1つの README にまとめた文書だけがあり、実装の変化に追従できていなかった。業務のルールとシステムの振る舞いが同じ節に混ざっていたため、実装を反映するたびに業務知識まで書き換わり、どちらが変わったのかを追えなくなっていた。

候補は (a) 単一の README を最新化し続ける・(b) 機能単位のフラットな構成にする・(c) 業務知識・システム仕様・システム構成・意思決定記録に分ける である。

## 決定

`documentation-conventions` スキルの規約に沿い、(c) を採る。`docs/domain/`（業務知識）・`docs/specs/`（システム仕様）・`docs/architecture/`（システム構成）・`docs/adr/`（意思決定記録）・`docs/changes/`（変更の起票）に分ける。業務ルールは `BR-SHARED-<連番>`、受け入れ基準は `AC-<機能>-<連番>`、未確定事項は `Q-<連番>` で相互に参照する。参照は仕様から業務知識への一方向に保つ。

## 理由

- 業務のルールとシステムの振る舞いは変わる理由が違う。同じ文書に置くと、実装を反映する上書きで業務知識が失われる
- ID による参照があると、業務ルールが変わったときに影響する仕様を機械的に探せる
- (a) は1ファイルが際限なく伸び、どこを直せばよいか決められない
- (b) は業務知識の置き場がなく、機能を作り終えると業務知識も一緒に捨てられる

## 影響

- 実装を変えたときは、同じ変更のなかで該当する仕様を上書き更新する。文書を増やさず既存の ID を維持する
- 業務ルールの ID は主題に紐づく。業務領域を分割して文書を移動しても ID は振り直さない
- 用語の表記は用語集を唯一の正とする。講座・チャプター・レッスン・受講状況の表記を揺らさない
- `docs/domain/` と `docs/specs/` では実装の名前（クラス名・テーブル名・カラム名・ファイルパス）を本文に出さない。実装との対応は `docs/architecture/` と `docs/adr/` が受け持つ
- 稼働中の実装から復元した記述であるため、業務側の確認を経ていない。確認が必要なものは `docs/domain/open-questions.md` に切り出した
- 画面の仕様はこのリポジトリでは扱わない。画面側の文書は別のリポジトリが持つ
