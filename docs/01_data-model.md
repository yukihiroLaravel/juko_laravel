# データモデル仕様書

本アプリケーションのデータ構造について説明する。

## 全体像

本アプリケーションは大きく分けて以下の3つの領域でデータを管理している。

1. **講座構造**: 講師が作成する講座・チャプター・レッスンの階層構造
2. **受講管理**: 生徒の講座登録（受講）と、各レッスンの進捗追跡
3. **サポート機能**: お知らせ、タグ、仮登録、ログイン履歴など

---

## 講座構造

講座は以下の階層構造を持つ。

```
講座（Course）
  └─ チャプター（Chapter）  ※順序あり
       └─ レッスン（Lesson）  ※順序あり
```

- 講座は1人の講師に属する
- チャプターとレッスンはそれぞれ `order` カラムで並び順を管理する
- 各階層には公開状態（`public` / `private`）がある
- チャプターを `private` にすると、配下のレッスンも自動的に `private` になる
- 講座には任意で定員（`capacity`）を設定できる

### 受講期限

講座ごとに受講期限の種別を設定できる。実際の期限値は `course_deadlines` テーブルに保存される。

| 種別 | 動作 |
|------|------|
| `none` | 期限なし |
| `fixed_date` | 全受講者に同じ固定日付を適用 |
| `relative_days` | 受講開始日から指定日数後を期限とする（受講者ごとに異なる） |

## 受講管理

### 受講（Attendance）

生徒が講座に登録すると `attendances` レコードが作成される。この時点で、講座内の全レッスンに対して `lesson_attendances` レコードが `before_attendance` ステータスで一括作成される。

つまり **`lesson_attendances` は未着手のレッスンも含めて常に全レッスン分が存在する**前提である。

### レッスン受講進捗（LessonAttendance）

各レッスンの受講状態は以下の順に遷移する。

```
before_attendance（未着手）→ in_attendance（受講中）→ completed_attendance（完了）
```

- 新しいレッスンが講座に追加された場合も、既存の全受講者に対して `lesson_attendances` レコードが自動作成される
- チャプター内の全レッスンが `completed_attendance` になると、そのチャプターは「完了」と見なされる
- 講座の進捗率は「完了チャプター数 / 全チャプター数」で算出される

## お知らせ（Notification）

講座に紐づくお知らせ機能。講師が作成し、その講座を受講している生徒に表示される。

### 種別

| 種別 | 動作 |
|------|------|
| `always` | 表示期間内は何度でも表示される |
| `once` | 1回表示された後、既読として記録され非表示になる |

- `once` 種別の既読管理は `viewed_once_notifications` テーブルで行う
- 公開状態（`public` / `private`）と表示期間（`start_date` ～ `end_date`）で表示を制御
- 受講期限切れの場合、お知らせも閲覧不可となる

---

## タグ

講師が作成するラベルで、講座に紐付けて分類に使用する。

- タグは講師単位で管理される（講師Aのタグを講師Bは使えない）
- 講座とタグは多対多の関係（`course_tag` 中間テーブル）
- 講座に紐づいているタグは削除できない

## ユーザーと認証

### 講師（Instructor）

講師には2つのロールがある。

| ロール | `type` 値 | 説明 |
|--------|----------|------|
| 管理者 | `manager` | 他の講師を管理でき、配下講師のリソースにもアクセス可能 |
| 通常講師 | `instructor` | 自身のリソースのみ管理可能 |

管理者と通常講師の紐付けは `manage_instructors` テーブルで管理される。

### 生徒（Student）

- 講師から直接登録されるか、仮登録フロー（メール認証）を経て本登録される
- `last_login_at` でログイン状況を追跡
- `student_login_histories` テーブルでログイン履歴を記録し、ログイン率分析に使用

### 仮登録

生徒・講師ともに仮登録→メール認証→本登録のフローを持つ。

- `temporary_students` / `temporary_instructors` テーブルに仮データを保存
- 4桁の認証コードと10桁のトークンで本人確認
- 有効期限は60分、認証試行は3回まで

---

## 論理削除

以下のモデルは論理削除（SoftDeletes）を使用しており、削除しても `deleted_at` にタイムスタンプが入るだけでデータは残る。

- Instructor, Student, Course, Chapter, Lesson
- Attendance, LessonAttendance
- Notification, ManageInstructor

以下は物理削除される（SoftDeletes未使用）。

- Tag, CourseDeadline, ViewedOnceNotification
- TemporaryStudent, TemporaryInstructor, StudentLoginHistory

---

## 削除時の制約と連鎖

| 操作 | 連鎖動作 |
|------|---------|
| 講座を削除 | 配下のチャプター・レッスン・期限設定も削除される |
| チャプターを削除 | 配下のレッスンも削除される |
| 受講を削除 | 関連するレッスン受講レコードも削除される |

| 操作 | 制約 |
|------|------|
| 受講者がいる講座を削除 | 不可（エラー） |
| レッスン受講がある章/レッスンを削除 | 不可（エラー） |
| 講座に紐づくタグを削除 | 不可（エラー） |
