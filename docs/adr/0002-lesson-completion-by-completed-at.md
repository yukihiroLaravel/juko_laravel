# ADR-0002 レッスンの完了を完了日時で判定し、その値を単調に保つ

## ステータス

承認済み (2026-08-17 記録)

この決定は実装済みの設計を後から記録したものである。決定そのものは記録日より前に行われている。

## 背景

受講状況は未着手・受講中・完了の3段階を持ち、受講生が自分で段階を戻せる。学び直しのために完了から受講中へ戻す操作が想定されるため、段階だけを見て完了を判定すると、過去に完了した事実が消えてしまう。修了率や学習履歴は「過去に完了したか」を必要とする。

候補は (a) 段階のみで判定する・(b) 完了日時を別に持ち、完了の判定はその値で行う・(c) 段階の変更履歴をテーブルとして持つ である。

## 決定

受講状況に完了日時を持ち、完了の判定は完了日時が記録されているかで行う。段階は表示のためのものとする。完了日時は一度記録したら上書きせず、段階が戻っても取り消さない。

## 理由

- 完了した事実は履歴として残す必要があるが、段階は受講生の操作で行き来する。性質が異なる2つを1つのカラムで表現できない
- (a) は学び直しで完了実績が失われ、修了率が下がる。集計の信頼性を損なう
- (c) は履歴の追跡としては正確だが、集計のたびに履歴を畳み込む必要があり、必要な要件に対して重い
- 完了日時を単調に保つことで、まとめて完了にする操作を何度実行しても結果が変わらない

## 影響

- 完了日時が未記録のものにだけ現在時刻を書き込む必要があり、更新処理は2段階になる
- 段階と完了日時が食い違う状態が正常な状態として存在する。段階だけを見た集計は正しくない
- 講師向けの期間集計は段階と最終更新日時を使っており、この決定に沿っていない（Q-002）
- 完了を取り消す業務要件が生じた場合、この設計では対応できない
