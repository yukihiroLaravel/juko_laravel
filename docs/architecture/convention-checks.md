# 規約の検査手段

`coding-standards.md` と `documentation-rules.md` に定めた規約を、どこまで機械で判定できるかを整理する。エージェントを使った開発では、規約を文章で示すだけでは守られたかどうかを確かめられない。この文書は、どの規約を機械の検査に載せ、どの規約を人間のレビューに残すかを決めるための対応表である。

既存コードには規約策定前の書き方が残っており、一括での作り替えは行わない。そのため「既存の違反を許したまま、新しく増える違反だけを落とす」という扱いが要る。区分 B がそれにあたる。

## 判定の区分

| 区分 | 意味 | 扱い |
|---|---|---|
| A | 機械で判定でき、既存の違反が 0 件 | 直ちに検査に載せ、違反があれば落とす |
| B | 機械で判定できるが、既存に違反がある | 基準線を記録し、そこから増えた分だけを落とす |
| C | 機械で検出できるが誤検知が混ざる | 警告として出し、落とさない |
| D | 機械で判定できない | レビューの観点として残す |

区分 A と B が検査の対象になる。C は出すだけで判断は人に委ねる。D は検査に載せず、レビュー時の指摘項目として `coding-standards.md` の重大度と対応させる。

## 検査手段の割り当て

| 手段 | 受け持つ範囲 | 実行する場所 |
|---|---|---|
| Laravel Pint | 整形と PSR-12 | 編集直後・継続的インテグレーション |
| PHPStan レベル6 と基準線 | 型の誤りと型宣言の欠落 | 継続的インテグレーション |
| Rector | 旧い記法 | 継続的インテグレーション |
| 検査スクリプト | 本文の検索で判定できる規約 | 編集直後・継続的インテグレーション |
| `php artisan route:list --json` | ルートの名前と形 | 継続的インテグレーション |
| 人間 | 設計・命名・責務の妥当性 | レビュー |

検査スクリプトは 1 本にまとめ、編集直後のフックと継続的インテグレーションの両方から同じものを呼ぶ。判定を 2 か所に書くと、いずれ食い違う。

## 対応表

区分と既存の違反数は 2026-08-19 時点の実測である。数値は参考であり、検査を実装したあとはスクリプトの出力を正とする。

### コントローラー

| ID | 規約 | 区分 | 判定手段 | 既存の違反 |
|---|---|---|---|---|
| CHK-CTRL-02 | サービスをコンストラクタで受け取らない | A | 検査スクリプト | 0 件 |
| CHK-CTRL-03 | トランザクションをコントローラーで管理する | C | 検査スクリプト | 6 ファイルで宣言あり |

CHK-CTRL-01 はコントローラーをシングルアクションにする規約だったが、2026-08-19 に規約ごと廃止した。番号は空けたままにする。

CHK-CTRL-03 は「サービス呼び出しを囲んでいるか」までは判定できない。サービス側に宣言がないこと（CHK-SVC-03）と対で見る。

### バリデーション

| ID | 規約 | 区分 | 判定手段 | 既存の違反 |
|---|---|---|---|---|
| CHK-VALID-01 | 1 エンドポイント 1 ファイルとする | A | 検査スクリプト | 0 件 |
| CHK-VALID-02 | Enum を定義している値の制御に `Rule::enum` を使う | A | 検査スクリプト | 0 件 |

CHK-VALID-02 は当初、`in:` の利用そのものを禁じていた。既存の 4 件はいずれも並び順の `in:asc,desc` であり、そのために Enum を新設すると割に合わない。2026-08-19 に規約を「Enum を定義している値だけ `Rule::enum` を使う」に改め、Enum を持たない単純な選択肢は `in:` を許すことにした。検査は、Enum が存在するのに `in:` で書いている箇所だけを見る。

### サービス

| ID | 規約 | 区分 | 判定手段 | 既存の違反 |
|---|---|---|---|---|
| CHK-SVC-01 | 公開メソッドは `__invoke` だけ | A | 検査スクリプト | 0 件 |
| CHK-SVC-02 | 複数のモデルが関与するものを置く | D | レビュー | — |
| CHK-SVC-03 | トランザクションを張らない | A | 検査スクリプト | 0 件 |
| CHK-SVC-04 | 入力は `validated()` の配列で受ける | D | レビュー | — |

CHK-SVC-03 はデータ整合性に直結するため重大度が `must` である。既存の 5 件は 2026-08-19 に修正し、トランザクションを呼び出し側のコントローラーへ移した。行ロックはトランザクションの内側でのみ効くため、ロックを使うサービスにはその旨を phpdoc に書いている。

CHK-SVC-01 の既存 5 件も同じ日に修正した。1 メソッドだけのサービスは `__invoke` へ改名し、2 つの処理を持っていた認証情報の生成サービスは `CreateCodeService` と `CreateTokenService` に分割している。未使用だったチャプター一覧の取得メソッドは削除した。

### モデル

| ID | 規約 | 区分 | 判定手段 | 既存の違反 |
|---|---|---|---|---|
| CHK-MODEL-01 | キャストを定義する | C | 検査スクリプト | 15 件中 2 件が `casts()` を持たない |
| CHK-MODEL-02 | password・token を `$hidden` に入れる | A | 検査スクリプト | 0 件 |
| CHK-MODEL-03 | 識別子カラムの Enum をキャストする | D | レビュー | — |

CHK-MODEL-01 はキャストが要らないモデルもあるため誤検知が出る。CHK-MODEL-02 は該当するカラムを持つモデルに限って見る。2026-08-19 に、受講生と講師には `password` を、仮登録の受講生と講師には `code` と `token` を宣言した。

CHK-MODEL-04 は主キーを `protected $primaryKey` で宣言する規約だったが、2026-08-19 に規約ごと廃止した。番号は空けたままにする。

### マイグレーションとテーブル設計

| ID | 規約 | 区分 | 判定手段 | 既存の違反 |
|---|---|---|---|---|
| CHK-MIGRATE-03 | 外部キーに `foreignIdFor` と `constrained` を使う | A | 検査スクリプト | 0 件 |
| CHK-MIGRATE-04 | テーブルとカラムに説明を付ける | C | 検査スクリプト | 84 件で付与済み |

CHK-MIGRATE-01 はテーブル名を単数形にする規約、CHK-MIGRATE-02 は主キーを `{テーブル名}_id` にする規約だったが、いずれも 2026-08-19 に規約ごと廃止した。番号は空けたままにする。

CHK-MIGRATE-05 は既存の 9 件を 2026-08-19 に修正し、区分 A に移した。`timestamps()` は `created_at` と `updated_at` を `dateTime` で明示する形へ展開している。

| CHK-ENUM-03 | 状態と種別をモデルのクラス定数で持たない | A | 検査スクリプト | 0 件 |

CHK-ENUM-03 は 2026-08-19 に対応した。受講状況の段階（`STATUS_*`）と講師の区分（`TYPE_*`）の 5 定数を Enum へ移し、参照 115 箇所を書き換えている。残っていた並び順・集計期間・進捗の初期値の 17 定数は、テーブルに保存される状態でも種別でもないため規約の対象外とした。検査は、モデルに定義された定数のうち `status` と `type` のカラムに対応するものだけを見る。

| ID | 規約 | 区分 | 判定手段 | 既存の違反 |

| CHK-TYPE-01 | 返り値と引数の型を宣言する | B | PHPStan レベル6 | 239 件（基準線に記録済み） |
| CHK-TYPE-02 | `CarbonImmutable` を使う | A | 検査スクリプト | 0 件 |
| CHK-TYPE-03 | `config` 以外で `env()` を呼ばない | A | 検査スクリプト | 0 件 |
| CHK-TYPE-04 | `empty()` を使わない | A | 検査スクリプト | 0 件 |

CHK-TYPE-01 は区分 B に残る唯一の規約である。2026-08-19 に PHPStan をレベル6へ上げ、その時点の 241 件を `phpstan-baseline.neon` に記録した。既存はそのまま通り、新しく書いたコードで型を省くと落ちる。

基準線は記録した違反が消えると「記録が古い」と知らせてくる。既存を直したときは `vendor/bin/phpstan analyse --generate-baseline` で記録を更新する。この性質があるため、直した分を取りこぼさずに減らしていける。

CHK-TYPE-04 の既存 4 件は、リクエストから受け取る講座の指定を `$request->collect()` に変え、`isNotEmpty()` で判定する形にして解消した。

## 区分 B の扱い

区分 B の扱いは 2 通りに分けた。仕組みを増やさないことを優先している。

| 対象 | 扱い |
|---|---|
| 型宣言（CHK-TYPE-01） | PHPStan の基準線に記録し、そこから増えた分だけを落とす |
| それ以外 | 違反を修正して 0 件にし、区分 A に移す |

型宣言は 239 件あり、修正しきるのは現実的でない。PHPStan の基準線は既存の機能であり、これを使うぶんには独自の仕組みが増えない。

それ以外の区分 B は 2026-08-19 にすべて修正し、区分 A へ移した。この結果、検査スクリプトは「違反が 0 件であること」だけを見ればよくなり、規約ごとの記録を持つ必要がなくなった。記録を持つ仕組みは、それ自体が更新の手間と食い違いの原因になるため作らない。
