## 適用範囲

すべてのエンドポイントに適用する。機能ごとの仕様書はこのファイルからの差分だけを書き、ここに書いた内容を再掲しない。認可の判定基準は `docs/specs/features/authorization.md` に集約する。

## 関連コンテキスト

主に `shared`（用語の定義は `docs/domain/shared/glossary.md` を唯一の正とする）。

## 認証と利用者の区分

利用者は受講生・講師・マネージャーの3区分であり、それぞれ入口となる経路が分かれている。マネージャーは講師の一種であり、講師向けの経路も利用できる。

1. `AC-COMMON-001` 認証を必要とする経路へ認証なしで要求があったとき、システムは 401 を返さなければならない。
2. `AC-COMMON-002` 受講生向けの経路へ講師として要求があったとき、およびその逆のとき、システムは 401 を返さなければならない。
3. `AC-COMMON-003` マネージャー向けの経路へマネージャーでない講師として要求があったとき、システムは 403 を返さなければならない。
4. `AC-COMMON-004` 認証は画面側のセッションを用い、要求は常に JSON として扱わなければならない。

## 一覧取得

5. `AC-COMMON-005` 一覧の絞り込み・並び替え・ページングは、すべてサーバー側で処理しなければならない（取得後の並び替えは不可である）。
6. `AC-COMMON-006` ページングは `per_page` と `page` で指定し、いずれも 1 以上でなければならない。指定がないときは一覧ごとの既定値を用いる。
7. `AC-COMMON-007` キーワード検索は部分一致とし、前後の一致位置を問わない。
8. `AC-COMMON-008` 複数の絞り込み条件が指定されたとき、システムは条件どうしを AND で結合しなければならない。1つの条件が複数の項目を対象にする場合、その項目どうしは OR で結合する。
9. `AC-COMMON-009` 絞り込み条件が指定されていないとき、システムはその条件による絞り込みを行ってはならない（0 件として扱わない）。
10. `AC-COMMON-010` 並び替えは指定できる項目を一覧ごとに限定し、それ以外を指定されたときは 422 を返さなければならない。並び順は昇順と降順のみとする。
11. `AC-COMMON-011` 該当が 0 件のとき、システムは空の一覧とページング情報を返さなければならない（404 としない）。

### 一覧ごとの既定値

| 一覧 | 1ページの既定件数 | 件数の上限 | 並び替えの既定 |
|---|---|---|---|
| 受講生の受講一覧 | 6 | なし | 指定なし |
| 受講生のお知らせ一覧 | 20 | なし | 掲示開始日時の昇順 |
| 講師の講座一覧 | 6 | 100 | 指定なし |
| 講師のお知らせ一覧 | 20 | なし | 指定なし |
| 講師の受講生一覧 | 10 | なし | 受講生の呼び名の昇順 |
| マネージャーの講座一覧 | 6 | なし | 講座の登録順 |
| マネージャーの講師一覧 | 20 | 100 | メールアドレスの降順 |
| マネージャーの講師別講座一覧 | 6 | なし | 指定なし |
| マネージャーの受講生一覧 | 10 | なし | 受講生の呼び名の昇順 |

並び替えの既定が「指定なし」の一覧は、並び順を明示していないため結果の順序を保証しない。順序に依存した利用はできない。

### 検索できる項目

| 一覧 | キーワードの検索対象 | その他の絞り込み |
|---|---|---|
| 受講生の受講一覧 | 講座名・タグ名 | タグ |
| 講師の講座一覧 | 講座名・タグ名 | タグ |
| マネージャーの講座一覧 | タグ名（Q-010） | タグ |
| 講師の受講生一覧 | 受講生の呼び名・メールアドレス・氏名 | 講座・受講開始日の範囲 |
| マネージャーの受講生一覧 | 受講生の呼び名・メールアドレス・氏名 | 講座・受講開始日の範囲 |

12. `AC-COMMON-012` 受講生を氏名で検索するとき、システムは入力された空白を取り除いたうえで、姓と名をつなげた文字列に対して部分一致で照合しなければならない。
13. `AC-COMMON-013` 受講開始日の範囲は開始日時と終了日時をそれぞれ任意に指定でき、片方だけの指定を許さなければならない。範囲は両端を含む。

## 更新と削除

14. `AC-COMMON-014` 複数件をまとめて更新・削除する操作では、1件でも実行できないものが含まれるとき、システムは全体を中止し、1件も変更してはならない。
15. `AC-COMMON-015` 更新・削除は、他の要求と混ざっても中途半端な状態が残らないよう、ひとまとまりの処理として実行しなければならない。
16. `AC-COMMON-016` 一覧に対する一括操作では、対象として指定された要素がすべて操作者の権限の範囲内にあることを確認してから実行しなければならない。範囲外のものが1件でも含まれるときは 403 を返す。
17. `AC-COMMON-017` 削除は原則として記録を残す取り消しとし、後から参照できる状態を保たなければならない。ただし仮登録の情報、お知らせの確認済みの記録、講座の受講期限の設定、タグは記録を残さず完全に削除する。

## 応答

18. `AC-COMMON-018` 登録・更新・削除が成功したとき、システムは処理結果が真であることを示す応答を返さなければならない。件数を伴う一括操作では、あわせて処理した件数を返す。
19. `AC-COMMON-019` 取得系の応答は、要求した利用者の区分に応じて必要な項目だけを返さなければならない。認証情報および他人の個人情報は含めない。

## エラー

| 状況 | 応答 |
|---|---|
| 認証されていない | 401 |
| 区分が合わない経路への要求 | 401 |
| 権限がない、受講期限を過ぎている、対象の状態が操作を許さない | 403 |
| 指定された対象が存在しない、または削除済み | 404 |
| 入力値が検証に通らない | 422 |
| 認証コードの検証に失敗した | 400 |

20. `AC-COMMON-020` 入力値の検証に失敗したとき、システムは項目ごとの理由を伴う 422 を返さなければならない。
21. `AC-COMMON-021` 削除済みの対象が指定されたとき、システムは存在しないものとして 404 を返さなければならない。

## 日付と日時

| 用途 | 形式 |
|---|---|
| 受講期限・固定の期限日・誕生日の入力 | `Y-m-d` |
| お知らせの掲示期間・一覧の検索範囲の入力 | `Y-m-d H:i:s` |
| 受講期限の応答 | `Y-m-d` |
| 誕生日の応答 | `Y/m/d` |

22. `AC-COMMON-022` 日付だけを持つ値を期限として判定するとき、システムはその日の終わり（23 時 59 分 59 秒）まで有効として扱わなければならない。
23. `AC-COMMON-023` 日時は日本の時間帯で解釈しなければならない。

## 画像

24. `AC-COMMON-024` 講座のサムネイル画像とプロフィール画像は JPEG または PNG のみを受け付け、1 ファイルあたり 2 MB を上限としなければならない。
25. `AC-COMMON-025` 画像を差し替えたとき、システムは差し替え前の画像を削除しなければならない。
26. `AC-COMMON-026` 画像を伴わない更新では、システムは差し替え前の画像を保持しなければならない。

## 対象外

- 画面の仕様（レイアウト・遷移・表示制御）。このリポジトリは API のみを提供する
- カーソル方式のページング。ページ番号方式のみを提供する
- 一覧の取得結果に対するキャッシュ
- 利用者向けの多言語対応
