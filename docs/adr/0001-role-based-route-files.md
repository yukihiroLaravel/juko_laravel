# ADR-0001 ルート定義をロール別のファイルに分割する

## ステータス

承認済み (2026-08-17 記録)

この決定は実装済みの設計を後から記録したものである。決定そのものは記録日より前に行われている。

## 背景

エンドポイントが 100 を超え、`routes/api.php` の1ファイルにすべての定義が並んでいた。受講生・講師・マネージャーで必要なミドルウェアと接頭辞が異なり、ネストが深くなるため、どのエンドポイントにどのミドルウェアが効いているかを読み取りづらい状態になっていた。

候補は (a) 単一ファイルのまま維持する・(b) ロール別のファイルに分割する・(c) コントローラーの単位で分割する である。

## 決定

ロール別のファイルに分割し、ミドルウェア・接頭辞・ルート名のネストは `routes/api.php` だけが持つ。

## 理由

- ロールごとに適用するミドルウェアが決まっているため、分割の境界がミドルウェアの境界と一致する
- ネストの定義を1か所に集約すると、あるファイル内のエンドポイントに効く前提条件が1行で分かる
- (c) はコントローラーの分割方針が変わるたびにファイル構成が動くため採らなかった
- (a) は差分の衝突が起きやすく、レビュー時に影響範囲を追いづらいため採らなかった

## 影響

- 新しいエンドポイントは、対象のロールのファイルに追加する
- マネージャー向けの経路は講師認証の内側にネストしているため、マネージャーのファイルに書いたものは講師の認証も通過する
- ミドルウェアや接頭辞を変えるときは `routes/api.php` だけを直す
- ロールをまたぐエンドポイントを作る場合、この構成では置き場所が決まらない。必要になった時点で構成を見直す
